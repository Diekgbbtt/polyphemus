# app - module context (technical supporting layer)

`src/polymerhus/app/` is the shared technical supporting layer the bounded contexts sit on.
It owns no domain language of its own (see `CONTEXT-MAP.md`), yet its sub-modules carry the fundamentals every context's runtime depends on.
This file records those fundamentals and the implementation patterns to repeat.
It is explicitly not a bounded-context glossary: the meaning of what these modules persist, execute, or invoke belongs to the consuming contexts.

## Sub-modules

- `llm/` - the LLM client layer: the provider table and client construction (`providers.py`), the role registry and the one-shot/session seams (`roles.py`, `session.py`, `actor.py`), the provider-failure classifier (`provider_failure.py`, #329), the transient-upstream classifier and retry policy (`transient.py`, #299), parsing-error recovery at the session seam (`parsing_recovery.py`), the durable token-usage ledger and its per-project store (`usage.py`, #326), capability negotiation (`capability.py`, `negotiation.py`), reasoning replay (`reasoning.py`), context compaction (`compaction.py`), the product-skill loader (`skills.py`), the gateway sync (`sync.py`, `sync_mapping.py`), and the conversation scope (`conversation.py`).
- `auth/` - the per-project shared auth store and its agent tool (`store.py`, `tool.py`, `records.py`); the operator seed face is a thin adapter over the same seam (`project_management/api.py`).
- `atomic_write.py` - the ONE construction point for the atomic whole-file write idiom: `write_text_atomic` / `write_bytes_atomic` write a caller-rendered body to a same-directory temp file (`flush` + `fsync`) and `os.replace` it onto the target, so a reader sees either the previous or the new complete file, never a truncated one (#340).
- `data_root.py` - the one layout owner for the app-owned data root (`<repo>/data/`): every store resolves its bucket through `project_dir`, so no module hand-builds a path.
- `runtime.py` - the module runtime/registry: run holds and the session lifecycle.
- `observability/` - Langfuse callbacks and tracing: the enabled gate + resolved base URL (`langfuse_tracing.py`), the handler seam, the ONE observation-delivery primitive (`flush_observation_delivery`) and its exporter-outcome result (`RetryingSpanExporter`), and the analyser step records.
- `gateway_entrypoint.py` - the container entrypoint: proxy first, health poll, sync, then the agent ASGI.
- `clients/`, `config.py`, `logging_config.py`, `main.py` - the HTTP/ASGI shell and process configuration.

## Fundamental decisions

- **One construction point per concern.** Every LLM client is built by `build_chat_model` (`llm/providers.py`), which the session and one-shot seams and every module share. Every storage path resolves through `data_root`. Store writes go through the owning store (`write` / `replace_operator_state`), never around it: the agent tool and the operator API are thin adapters.
- **Configuration is read through the module, never bound by value at import.** `config.py` owns one `config` object; a consumer reads `config_module.config` at the use site, so a module reload or an attribute replacement is always observed. An import-time `from polymerhus.app.config import config` captures the object and desyncs on reload, which polluted the test suite (#333); `ingestion/service.py` was hardened, and the remaining import-time bindings are a tracked follow-up of the same class.
- **Mode selection is one env var, never a branch per caller.** `LLM_GATEWAY_URL` unset means direct per-provider mode; set means the co-located gateway, which owns id translation and upstream routing (`docs/design/llm-gateway-100-decisions.md`, ADR D3/D5).
- **The client's gateway credential is an app-minted virtual key, never the provider credential.** In gateway mode `build_chat_model` derives `gateway_virtual_key(provider, API_KEY_<PROVIDER>)` (`sk-ph-<sha256>`) as its bearer, and the sync mints exactly that key scoped to the provider's registered models; the provider key still rides each model's `litellm_params.api_key` (the gateway's upstream custody). LiteLLM's inbound auth and `/key/generate` accept only `sk-`-prefixed virtual keys, so opencode-go's `oc_sk_` provider key can no longer be the inbound key (#335, ADR D3 amended 2026-10-06).
- **The gateway enforces a USD cost guard on each minted virtual key.** The sync provisions each provider key with LiteLLM-native `budget_limits` windows (5h/7d/30d) built from the same per-token costs it authors into each deployment's `model_info` - the provider-specific effective cost override where one exists, the models.dev record otherwise - scaled by a conservatism factor, plus an optional `rpm_limit`; a budget-exceeded request is rejected (429) at auth before the provider is called, and `fail_closed_budget_enforcement` rejects (503) when the spend is unverifiable. Provisioning is idempotent - the diff compares the canonical budget windows and ignores litellm's server-set `reset_at`, so a no-change re-run is a no-op (#330, ADR D13).
- **Provider policy lives in tables with safe defaults.** `PROVIDERS`, `_ID_KIND_BY_PROVIDER` / `id_kind()`, and `_REQUEST_HEADERS_BY_PROVIDER` / `request_headers()` are the one place a provider's policy sits; an unlisted provider gets the transparent default (verbatim ids, no bound headers), so a new provider is a one-line table entry.
- **A provider failure is a classified infrastructure condition, never domain data.** `provider_failure.py` is the ONE provider-failure classifier: a timeout/transport/429/5xx/quota raise is `ProviderUnavailableError` (typed, retryable, carrying the status and `Retry-After`), and anything else is non-provider. The actor retry layer (`actor.py::_is_retryable`) delegates to the transient classifier, so retry and classification agree by construction; the test-executor pod and the hunting runtime consume the same pair, so a throttle is neither fabricated into a pod verdict nor landed as a run `failed` (#329).
- **A transient upstream fault is ridden out, never failed on (#299).** `transient.py::classify_error(outcome, provider, model)` is the ONE turn-fault classifier: the provider-failure class plus the EXACT opencode-go deepseek single-model-echo 400 (operator ruling D-1: status 400 AND a body whose ONLY key is `model` equal to the configured deepseek wire id AND the opencode-go lane) is `transient`; a recognisable actionable 400 is `contract`; an empty 400, a foreign-model echo, a multi-key envelope, or anything unknown is `fatal` (fail-open, never retried). The lane identity is threaded from the caller (`actor._lane_identity`, or the `<provider>:<model>` one-shot label), so a model id alone never branches. `actor.py::_is_retryable` and the one-shot `invoke_with_escalating_timeout` delegate here, so no seam can drift. A transient fault is retried under a jittered, capped temporal backoff (`jittered_backoff`) to ride out a short window, and each retry rotates the provider conversation id (`rotate_conversation`: `<thread_id>#r<attempt>`) to abandon a pinned bad upstream replica - while the checkpointer keeps `thread_id`, so agent memory is never forked. On transient exhaustion a configured fallback model (`providers.resolve_fallback`: `LLM_FALLBACK_<ROLE>` then `LLM_FALLBACK_MODEL`) is attempted exactly once, so a lane outage cannot silently drop a recon extraction (#285) and cannot mask a sustained one; a non-transient 400 never arms it. `record_transient` emits one structured record and counter increment per transient attempt, so a recurring window is visible before it kills a run.
- **Fail-open at read boundaries, fail-loud at write boundaries.** A missing or unreadable store file reads as a valid empty, loudly; a write that cannot read its target refuses (`store_unavailable`) rather than overwriting blind; a shape violation refuses with a coded error naming the field.
- **The tracing gate matches the tracing resolver.** Tracing is enabled only when `LANGFUSE_PUBLIC_KEY` + `LANGFUSE_SECRET_KEY` + at least one of `LANGFUSE_BASE_URL` / `LANGFUSE_HOST` are set (`#327`), the same alias resolution the SDK performs; the disabled reason names the actual missing value. The pinned SDK is the v4 major, so the code uses the v4 observation model (`propagate_attributes`, `start_as_current_observation`) and emits only `langfuse-sdk` spans the default v4 export filter keeps, preserving the trace hierarchy.
- **A delivery result is truthful about the exporter, not just the queue.** `flush_observation_delivery` (the ONE observation-delivery primitive) reports a handler `delivered` only when its client's `flush()` drained AND the in-effect `RetryingSpanExporter` recorded no dropped spans in the window; an exhausted retry budget is `dropped` with cause `exporter-failed` (a raising flush stays `flush-raised`). The wrapper keeps a monotonic dropped-span counter that the primitive reads-and-resets AFTER the drain, so a drop during the window - or since the previous read - can never be reported as `delivered`, and the read shares a lock with the increment so a racing drop is never lost. Truth is sourced from the exporter actually in effect (`client._resources.span_exporter`), not a private registry that could name an unused wrapper. Every module run-end flush (analyser tracing, analysis supervisor/bootstrap, hunting, orchestrator) delegates here, so no parallel SDK-client flush path can report a false success; delivery stays fail-open, and only the RESULT is truthful (#235, `docs/design/observability-delivery-truth-235-adr.md`).
- **Server-stamped facts are never trusted from the client.** `origin` and `updated_at` are stamped server-side on every write and seed; a client-supplied value is dropped, never merged.
- **Ambient context is scoped, not global.** Cross-cutting identity travels in ContextVars (`conversation_scope`, the checkpoints module context, the runtime run hold); each is set for a bounded scope and restored on exit, so nothing leaks between turns or sessions.
- **Bind at the native layer before wrapping.** Where the stack already has the mechanism, use it: client request headers ride `ChatOpenAI.default_headers` (the SDK threads them into the httpx client), never hand-rolled request mutation. The reasoning-passthrough subclass is the one justified wrapper, and its SDK-internal seams are pinned by contract tests that turn red on a version bump.
- **Durability is per-record, not per-file.** Every store write is atomic through the shared `app.atomic_write` primitive (caller-rendered body -> same-directory temp file + `flush` + `fsync` + `os.replace`) and serialised per project (one lock per id covering the whole check-then-write), so concurrent writers converge instead of forking records and an aborted write never truncates the target. The primitive is the one construction point for the idiom; the private copies in the auth and skill stores are retired (#340).
- **A process-wide accumulator that must survive the process is write-through, not boundary-only.** The usage ledger records each model call in memory and write-throughs the touched project's cumulative entries to its per-project file store on every `record`; the first use of a project in a process read-throughs the durable floor back in, so a restart resumes the true cumulative spend and a resumed project never double-counts (the store is REPLACED with the cumulative total, never appended to). `flush`/`flush_all` at the stop/drain/shutdown boundaries are a safety net, not the load-bearing path: the observed #326 loss was a process death between boundaries (a hunting run reconciled to `interrupted` at startup), which boundary-only flushing cannot recover. Reads and persists are fail-open, so durability never breaks an agent turn (#326, `docs/design/usage-ledger-durability-326-adr.md`).
- **A checkpointed trail must satisfy the tool-call/response pairing contract.**
  The upstream now enforces pairing only - a valid or malformed assistant tool call with no answering `tool` message is rejected with HTTP 400, and symmetrically a `tool` message with no preceding assistant call is rejected too, so the pairing contract must hold in BOTH directions - while the arguments' JSON validity is irrelevant, so an error `ToolMessage` answer is a complete, contract-valid repair; the pinned wire serializer (`langchain_openai.chat_models.base._convert_message_to_dict`) emits both `tool_calls` and `invalid_tool_calls` as `tool_calls`, which is why a checkpointed parse failure poisons every later request.
  `create_agent` never ported `AgentExecutor.handle_parsing_errors` (langchain issue #33504, PR #35818 closed unmerged), so the session seam owns the recovery: `app/llm/parsing_recovery.py` is wired FIRST in `session._build_agent`.
  Its `after_model` answers the TAIL REQUEST's unanswered `invalid_tool_calls` entries with an error `ToolMessage`, jumping back to the model for a bounded in-turn retry - where the tail request is the last assistant tool-call request whose only trailing messages are its own `tool` answers.
  Walking back over those trailing answers is what covers the structured-output path (F13): `create_agent._handle_model_output` appends the structured call's answer INSIDE the model node, so a sibling malformed ordinary call - the observed `graph_view` case - would otherwise sit one message behind the literal tail and stay unanswered (the ordinary-tool sibling of #296's malformed structured call, which the literal tail already covered).
  The answer is appended at the tail; a `HumanMessage` (or a later assistant message) is a stop boundary and is never crossed, so answering a stale call before one would append a `tool` message with no adjacent call (an orphan answer, rejected symmetrically) - the #280 follow-up, where the old whole-trail scan did exactly that.
  The jump is suppressed when the turn is already resolving (a trailing `tool` answer) or a valid `tool_calls` entry is still unanswered and ToolNode must run it; jumping there would bypass the tools routing and leave that valid call unanswered.
  Valid `tool_calls` are never touched - ToolNode owns those and runs after `after_model`.
  Its `before_model` reconciles a RESUMED turn positionally: the seam reads the framework's pending-next variable (`StateSnapshot.next`) before invoking and passes it as `session_pending_next` metadata, and only then does `before_model` insert each missing answer immediately after the assistant call it answers, because the upstream requires the tool answer to directly follow the call.
  The read sits at the seam because the module checkpointer prunes to the latest checkpoint per thread, so the interrupted parent tuple is gone once the new input is written.
  A normal, completed turn carries no signal and is left untouched, so pre-existing completed-turn poison is deliberately not auto-repaired.
  Recovery never drops or rewrites a message to hide the violation from the wire (#280).

## Patterns to repeat

- Provider request primitives live in the provider table and are evaluated at construction (D12): the session seam binds the conversation as an ambient scope, the construction reads it, and unlisted providers stay byte-identical.
- A retry that must ride out an upstream window rotates the PROVIDER conversation primitive, never the durable identity: `conversation_id` overrides only `conversation_scope` (the wire `x-opencode-session`), while the checkpointer's `thread_id` and the turn's reported `thread_id` stay the original, so memory is never forked (#299).
- A pattern that fails open (tracing, capability resolution, an absent conversation) must say so loudly and never gate the caller; fail-loud is reserved for write corruption and contract violations.
- Write the decision down in the owning ledger before or with the code, and keep the module path pointers honest.

## Glossary

- **atomic write primitive** - `app.atomic_write.write_text_atomic` / `write_bytes_atomic`, the ONE construction point for a whole-file rewrite: the caller renders the complete body in memory, the primitive writes it to a same-directory temp file, `flush`es and `fsync`s it, then `os.replace`s it onto the target (an atomic rename on POSIX), unlinking the temp best-effort. It guarantees a reader sees either the previous or the new complete file, never a truncated one, and a crash after the rename leaves a durable complete file. It replaces the private per-store copies; the `fsync` is deliberate because the rename orders but does not force the new bytes to disk (#340).
- **gateway virtual key** - the client's inbound identity to the co-located LiteLLM gateway in gateway mode: an app-minted, `sk-`-prefixed virtual key derived deterministically per provider by `providers.gateway_virtual_key` (`sk-ph-<sha256(provider NUL api_key)>`). The sync mints exactly that key (`sync.GatewayClient.ensure_virtual_key`, scoped to the provider's registered models, idempotent per C9) and the client presents it as its bearer, so the two agree with no persisted mapping and no new env var. It is NOT the provider credential (which litellm rejects unless `sk-`, and which stays in the model's `litellm_params.api_key`); `API_KEY_<PROVIDER>` is only its derivation seed (#335, ADR D3 amended 2026-10-06).
- **gateway cost guard** - the per-virtual-key USD budget the sync provisions in gateway mode (#330, ADR D13): LiteLLM-native `budget_limits` windows (5h/7d/30d) plus an optional `rpm_limit`, derived from the provider's dollar-denominated cap and the effective per-token costs (the provider cost override where one exists, the models.dev record otherwise). It rejects a budget-exceeded request (429) at auth before the provider is called; `general_settings.fail_closed_budget_enforcement` rejects (503) when the spend is unverifiable. It is idempotent (the diff ignores litellm's server-set `reset_at`) and it never fails the run outright - a gateway throttle is a provider failure, classified by `provider_failure.py`.
- **conservatism factor** - the scalar `k` (`LLM_GATEWAY_BUDGET_CONSERVATISM_FACTOR`, default 0.5) by which every provider cap is multiplied to size the cost-guard windows. It compensates for peak/off-peak pricing: the sync authors the effective OFF-PEAK rate (the provider cost override where one exists) while opencode-go charges 2x at peak, so LiteLLM undercounts actual peak spend by up to 2x and the budget must trip at half the dollar cap to trip before the provider does. A factor above 1 is a config lie (it would exceed the provider cap) and is rejected.
- **observation-delivery primitive / exporter drop** - `flush_observation_delivery` (`app/observability/langfuse_tracing.py`) is the ONE drain of the Langfuse background exporter: it flushes each borrowed handler's own client and returns a truthful `DeliveryResult` (`delivered`/`pending`/`dropped`, closed `cause`). An **exporter drop** is a batch whose `RetryingSpanExporter` retry budget was exhausted; the wrapper counts its spans monotonically and the primitive reads-and-resets the counter AFTER the drain, so an exporter drop is `dropped`/`exporter-failed` and can never be reported as `delivered` (the pre-#235 queue-drain lie). Every module run-end flush delegates here.
- **pricing-gap (budget fail-open)** - the condition of a registered model whose authored `model_info` carries no USD price. LiteLLM cannot estimate its max request cost, so budget reservation is skipped and the USD cost guard FAILS OPEN for it (LiteLLM #35524; `block_requests_for_models_without_pricing` does not exist in the pinned 1.96.0). The policy is to keep eval/hunting role models priced (models.dev or a provider cost override) and to make the gap loud: the sync logs every unpriced registered model at bootstrap.
- **provider cost override** - the operator-authoritative correction of a provider offering's effective per-token price, held in `sync_mapping.PROVIDER_COST_OVERRIDES` keyed by the registered `<provider>/<model_id>` name, applied LAST in the `model_info` authoring on every sync (#330 iteration 2, ADR D13 amendment 2026-10-06). It wins over the models.dev record because a litellm-config-only override is clobbered by the sync's models.dev re-authoring. The seeded entry is opencode-go's OFF-PEAK rate for `deepseek-v4.1-flash` (models.dev prices it ~6x higher), the default because ~90% of eval wall-time is off-peak; the conservatism factor handles the 2x peak. An overridden record carries `cost_source: provider-override` while its capability provenance stays models.dev-sourced. Keyed by the registered name, not the models.dev record, it survives a models.dev price change and a dropped record; an unreachable configured override is logged loudly.
- **provider failure** - an LLM-provider infrastructure raise (429 throttle or quota, 5xx, timeout, or transport error), classified by `app/llm/provider_failure.py` and surfaced as `ProviderUnavailableError`. It is distinct from a domain error: it is retryable, it carries `status_code` / `retry_after_s` / `quota_exhausted`, and it must never be encoded in domain data (a pod verdict) or fail a run outright (#329). `quota_exhausted` distinguishes a period-quota exhaustion (`Go usage limit exceeded`) from a transient per-minute throttle. `interrupt_reason()` renders the classifier's cause as one operator-readable line plus the machine-readable `provider_status`/`quota_exhausted`/`retry_after_s`, which the hunting runtime stamps on an `interrupted` run's `stats` so the cause (including the `quota_exhausted` flag) survives the process for the eval resume policy (#331). A provider failure in a dispatched HUNTER or POD session rides the same terminal: it records on the run-local `RunDispatchState`, the surfer surfaces it, and `start_hunting` maps it to `interrupted` + `stats` (#312), so no hunting phase quiesces `complete` while silently producing nothing. The eval does not yet consume the flag to classify transient vs consumed credits; that wiring is deferred to the operator ruling.
- **transient upstream fault** - a fault the app can ride out rather than fail on, classified by `app/llm/transient.py` (#299). The transient-400 leg is the EXACT opencode-go deepseek lane signature (operator ruling D-1): status 400 AND a body whose ONLY key is `model`, whose value equals the configured deepseek wire id (`deepseek-v4.1-flash`, or the `deepseek-v4-flash` variant of #285), AND the opencode-go lane identity. The header leg is UNVERIFIED (no discrete header was confirmed from the live capture). It is distinct from a `contract` 400 (a recognisable actionable body - `MissingSessionID`, `reasoning_content`, `response_format`, `top_p`, `tools[].function` - which fails fast) and from `fatal` (an empty 400, a foreign-model echo, a multi-key envelope, or anything unknown - fail-open, never retried, never arming the fallback). A transient fault is retried with a jittered temporal backoff and a rotated provider conversation id (`<thread_id>#r<attempt>`), then a single bounded fallback model on transient exhaustion; `record_transient` counts each attempt by `(role, model, body_shape)`.
- **conversation rotation** - the per-attempt provider conversation id a transient retry binds (`transient.rotate_conversation`): attempt 0 is the thread's own id, later attempts append `#r<attempt>`. It reaches only the provider request primitive (`x-opencode-session`) through the session turn's `conversation_id` override; the checkpointer's `thread_id` and the turn's reported `thread_id` do not rotate, so agent memory is never forked (#299).
- **usage ledger** - the process-wide, per-project, per-agent token accumulator (`app/llm/usage.py`) the session seam records into and the app API exposes read-only as a two-axis typed surface: `context_tokens` (`cached` from `input_token_details.cache_read`; `uncached` = `input_tokens - cache_read`, because on the pinned path `input_tokens` is INCLUSIVE of cache_read) and `generated_tokens` (`reasoning` from `output_token_details.reasoning`, `visible` from output minus reasoning), plus the raw scalar `total_tokens` (context + generated) and the scalar `capped_tokens` (generated + uncached = `total_tokens - cached`, the trial token-budget axis, #347). The trial's token-budget axis is `capped_tokens` (new output plus uncached input), so cached input the model re-reads never consumes it (2026-10-08). A missing/blank project id lands in the unscoped bucket, which a project snapshot never returns. It is DURABLE (#326): each `record` write-throughs the project's cumulative entries to a per-project file store (`UsageStore`, `<data_root>/<project_id>/usage/usage.yaml`), and the first use of a project in a process read-throughs that record back in, so a project's spend and its per-agent breakdown survive a restart, a stop, or a drain; `flush`/`flush_all` persist at the stop/drain/shutdown boundary as a safety net.
- **voluntary function calling** - the A6 negotiated rung for a model whose upstream refuses a forced `tool_choice`: the schema tool is bound, the choice is not forced, the provider decides (a relaxed model rewrites the force to `"auto"` at bind time).
- **capability override** - the operator-declared correction of a registry claim, via `LLM_CAPABILITY_OVERRIDES` (e.g. a thinking-mode relay refusing a forced tool choice that models.dev cannot express).
