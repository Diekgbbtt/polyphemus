# Canonical runtime requirements for the polymerhus agent application (#100).
#
# Source of truth for the FULL app dependency set. Previously these were
# provided implicitly by the `redamon-agent` base image (a legacy name from
# another project that no longer exists in the docker daemon and cannot be
# pulled - `insufficient_scope`, verified 2026-08-17). The Dockerfile now
# builds from `python:3.11-slim` directly, so THIS file is what recreates the
# app runtime the base used to bake in.
#
# Version alignment: pins mirror the python:3.11 base's original wheel set
# (redamon/agentic/requirements.txt: python 3.11-slim + the langchain family)
# and the repo's own pinned requirements (requirements-dev.txt /
# requirements-gateway.txt). A bump is a one-file review here, never a
# base-image rebuild (ADR D10 discipline).
#
# The langchain family:
#   - langchain-core: the message/output primitives the LLM seam imports
#     (`langchain_core.messages`, `langchain_core.outputs`).
#   - langchain: the full agent runtime - the session path
#     (app/llm/session.py) runs long-horizon tool-calling agents via
#     `langchain.agents.create_agent`, and the actor/orchestrator seams bind
#     `langchain.agents.middleware.AgentMiddleware` (the langchain 1.x agent
#     API; langchain-core alone does NOT provide `create_agent`).
# EXACT pins per ADR A4 (#99): the capability-adaptive method negotiation
# relies on `with_structured_output` semantics that silently changed across
# SDK bumps (0.3.12 vs 0.3.21 - a floor-bound is not a pin), and
# `ReasoningPreservingChatOpenAI` (providers.py) pins langchain-openai 1.3.x
# internals (`_create_chat_result`, `_get_request_payload`). The pin-behavior
# tests (tests/test_llm_structured_output_pin.py) turn red on purpose if a
# pin moves; the resolved lock is langchain 1.3.14, langchain-core 1.5.3,
# langchain-openai 1.3.2, langgraph 1.2.7.
langchain==1.3.14
#   - langchain-openai: the ChatOpenAI client `build_chat_model` constructs
#     (the single LLM transport; every provider is an OpenAI-compatible
#     HTTP endpoint, ADR D1).
#   - langchain-mcp-adapters: the MCP client/tool adapter the crawl and
#     recon tool seams use.
#   - langgraph: the StateGraph engine behind the recon/analysis/hunting
#     supervisors (recon/control/job_agent.py, analysis/supervisor.py,
#     attack/hunting/orchestrator_graph.py, the crawl/recon pod graphs).
#   - langgraph-checkpoint-postgres: the durable session checkpointer
#     (app/clients/pg.py, `AsyncPostgresSaver`); pulls psycopg.
langchain-core==1.5.3
langchain-openai==1.3.2
langchain-mcp-adapters>=0.1
langgraph==1.2.7
langgraph-checkpoint-postgres>=2.0.0

# Data stores (the shared postgres instance + neo4j).
psycopg[binary]==3.2.3
neo4j==5.27.0

# The agent ASGI surface + HTTP client (same pins as requirements-gateway.txt
# so the gateway and agent agree on the transport).
fastapi==0.140.6
httpx==0.28.1

# Model/validation + YAML config parsing.
pydantic>=2.0
pyyaml>=6.0

# The live-tier test infrastructure (tests/e2e drives in-container probes and
# the config contracts; fastmcp is the MCP server SDK the kali/test seams use).
fastmcp>=2.14,<3
