# ADR: the batched L1-unit-first analysis prompt variant

*Status: accepted for implementation 2026-10-12 (branch `feat/analysis-unit-enrichment`).*
*T0 built the selection seam; T1 rewrote the assigner prompt and re-parameterised its code workflow (section "The assigner (T1)"); T2 rewrote the mechanism-typist (section "The mechanism-typist (T2)"); T3 rewrote the data-modeller (section "The data-modeller (T3)"); T4 is the adversarial-review fix pass (section "The adversarial-review fixes (T4)"); T5 scopes the assigner rewrite to `service_sourced` and restores the legacy slice-based assigner for `streamed` (section "The streamed-mode guard (T5)").*

## Context

The v2 `service_sourced` pipeline (ADR `analysis-unit-enrichment-adr.md`) reasons from a pre-fed asset slice.
Every proposer receives the whole mapped L0 surface in its first user message.
A unit then drops every surface item whose best owner is a different Service, because the write filter admits only the unit's own slug.
One Service proposed 25 aggregates and kept 0, so placement fell below v1.
The root cause is the pre-fed surface plus the per-unit write scope, not the filter alone.

The replacement behaviour reasons L1-unit-first: the unit (a Service or a System) is the only context, and the proposer discovers its own surface through `graph_view` and the HTTP-history tools.
That behaviour needs three NEW prompt files.
The selection must be reversible, because the current prompt files are the only tested arrangement.

## Decision

1. **Keep the `service_sourced` mode value.** No new analysis mode is added; the mode selects the pipeline, not the prompt arrangement.
2. **Add `ANALYSIS_PROMPT_VARIANT`, defaulting to `batched_l1unit_first`.**
   The two values are `batched_l1unit_first` and `legacy`.
   The selector is read on call, never at import (CODING_STANDARD section 6).
   An absent value is the default; an unknown value logs a warning and coerces to the default.
3. **One shared helper owns the role-to-file map.** `analysis/prompt_variant.py` exposes `resolve_prompt_variant()` and `prompt_path(role_id, variant=None)`.
   `batched_l1unit_first` selects `<base>-batched-l1unit-first.md`; `legacy` selects `<base>.md`.
   The module imports none of the three role modules, so it stays a leaf.
4. **The three loaders resolve through the helper and memoize per variant.**
   `assigner._load_assigner_skill`, `mechanism_typist._load_skill`, and `data_modeller._load_skill` keep their FAIL-CLOSED read (a missing file raises) and their per-variant memo, so the system prefix stays byte-identical across a run.
5. **The original files are the rollback.** `legacy` reproduces the current prompts byte-for-byte - with ONE deliberate exception: decision 22 corrected the canonical `modelling-closure` note name in `data-plane.md` too, so that legacy file no longer reproduces the pre-change underscore token verbatim. The correction is intentional (a shared vocabulary must not drift between variants), and it is the only byte-level divergence.

## The assigner (T1)

T1 rewrites the assigner's HOW prompt (`assigner-batched-l1unit-first.md`) and re-parameterises its code workflow.

6. **The workflow is harvest, falsify, assign.** The assigner's sub-problem chain is `harvest_surface` (aggressively query `graph_view` and `search_http_history` from contract-derived candidate strings), `falsify_harvest` (try to throw each harvested Endpoint out against the contract), `prior_insights`, `candidate_owners` (the differential over the SURVIVORS), `assign`, `closure`.
7. **The settled surface is no longer pre-fed.** `assign` seeds the Service UNIT context (the slug, its `contract`, and the Service's OWN already-aggregated endpoints) plus the inventory; it no longer renders the whole admitted surface into a prompt. The full admitted set is still built from the chunk for the deterministic gates (`shape_proposal`): only the PROMPT feed is removed, never the validation set.
8. **No per-Service write filter.** `assign_services` judges each Service with the FULL live inventory (`existing_slugs=all_slugs`), so a Service may name ANY live Service as owner. The GLOBAL validation gate (`drop_out_of_inventory`) is unchanged: a slug that is not a live Service is still dropped.
9. **The HTTP-history pair is bound for every harvesting proposer.** `search_http_history` / `get_http_artifact` join `graph_view` on every assigner (and, for T2, mechanism-typist) turn, so the bound tool set matches the tools the rewritten workflow tells the model to call and stays constant across a run (the cache rule).

## The mechanism-typist (T2)

T2 rewrites the mechanism-typist's HOW prompt (`technical-system-batched-l1unit-first.md`) and re-parameterises its code workflow.

10. **The analysis object is the L1 UNIT, and the question has two directions.** The typist no longer reads "a streamed slice of a target's observable surface". Its unit is a Service OR a System (`service_slice.build_service_slices` appends both). A Service unit asks the CENTRAL question FORWARD: given the catalog, which technical Systems could this Service rely on to offer the service in its contract, and how is that contract implemented; which relied-upon Systems are not yet mapped. A System unit asks the SAME question in REVERSE: which Services rely on this overlay, and how. The unit kind selects the direction; the unit block states it.
11. **The workflow is the unit-first chain.** `orient_from_catalog` (read the RDF catalog, the bootstrapped Systems, and the unit; state the mechanism landscape) -> `harvest_surface` (discover the unit's surface through `graph_view` and the bound HTTP-history pair) -> `prior_insights` -> `mechanism_hypotheses` (the direction-dependent central question, with the fail-closed halt preserved) -> `page_clusters` -> `systems_extract` -> `link` -> `closure`. Every turn speaks the ONE `AnalysisTurn` envelope.
12. **The catalog, the bootstrapped Systems, and the unit ride the HumanMessage.** The base artifacts are the `unit` block (identifier, kind, description - the `service_contract` for a Service, the System `description` for a System - plus the Service's aggregated L0 endpoints), the `inventory` (the bootstrapped Systems with their descriptions, plus the live Service list), the `vocabulary` (every System `kind` and System-edge `rel`, via `l1_curator.vocabulary_prompt()`), the `observations`, and the linking `candidates`. None moves into the stable system prompt.
13. **The "read what exists; never filter on a path you guessed" rule is REVERTED for this role.** The typist now starts FROM the contract and hypothesises, then VERIFIES against the graph and the HTTP history. The old `unit_surface_read` turn is gone, replaced by `harvest_surface`.
14. **No per-unit `service_slug` write scope on `link`.** A Service unit may link a System to ANY live Service it genuinely overlays; a System unit may link to any rider. The `link` context names the full live Service inventory and marks PRIMARY a PRIORITY, never a restriction. The only surviving gate is the curator's global validation (a `rel` or `kind` outside the catalog is dropped) - a slug that is not a live Service is rejected by the write layer, never scoped by this role.

## The data-modeller (T3)

T3 rewrites the data-modeller's HOW prompt (`data-plane-batched-l1unit-first.md`) and re-parameterises its code workflow.

15. **The analysis object is the L1 UNIT (the Service).** The modeller no longer reads "a streamed slice of Parameter/Header/Secret surface". It reasons DOWN from the unit - the slug, the `service_contract`, and the Endpoints the Service already aggregates - and DISCOVERS its surface through `graph_view` and the bound HTTP-history pair. The opening paragraph is rewritten; the streamed-slice framing is gone. The load-bearing staged loop (Orient / Hypothesise / Verify-Falsify / Integrate / Shape / Emit, with the explicit null hypothesis) is kept verbatim, re-parameterised so the survey starts from the unit and the discovered surface.
16. **The workflow ids stay; the feeds are re-parameterised.** The chain is `surface_survey` -> `request_shapes` -> `insight_recall` -> `record_hypotheses` -> `data_extract` -> `flow_shape` -> `flow_extract` -> `closure_note`. `surface_survey` surveys downwards from the unit and emits `claims`; `request_shapes` drives its HTTP-history search from the Endpoints discovered in step 1. No sub-problem is fed a whole-streamed-surface list: the base sources are the `service` unit block (slug + `service_contract` + aggregated Endpoints), the `inventory` of known DataItems, the `services` block (the FULL live Service inventory) and the `observations`. The old `surface` (admitted-asset render) and `candidates` (per-asset owner join) sources are removed from the prompt; `admitted` still feeds the deterministic gates (`resolve_surface_refs`, `observed_vocabulary`).
17. **No per-unit `service_slug` write scope on `data_flows`; the global validation is kept.** The data-modeller already passes the FULL live inventory as `existing_slugs` (`frozenset(inv.get("services") or ())`); T3 confirms this and removes the prompt's per-asset candidate-list framing, so a flow may name ANY live Service as producer or consumer. `drop_out_of_inventory_services` is unchanged: a slug that names no live Service is still dropped, and the backlog still names it.
18. **The worked examples are rewritten from scratch.** The spurious L0chunk-first examples are replaced by the unit-first survey + hypothesise -> verify -> shape shape; the explicit null hypothesis, the reuse-over-paraphrase and the observed-only-fields examples survive, re-parameterised.

## The adversarial-review fixes (T4)

Three adversarial reviews (assigner, mechanism-typist, data-modeller) found real defects; all are fixed in the same change.

19. **The reference gate is fed the graph-discovered sites (C-M1, MAJOR).** Under unit-first discovery the model reaches sites through `graph_view` that the unit's pre-aggregated chunk never carried. The reference gate (`resolve_surface_refs`) and the observed-only gate (`bind_fields_to_observed`) resolved only against `site_index(admitted)` / `observed_vocabulary(admitted)`, so such a site could never ground an item. The gate now resolves against the UNION of the admitted chunk and a LIVE graph-backed identity index (`l0_stream.read_surface_sites`, filtered to Parameter/Header/Secret). The index is threaded as `read_sites_fn` from the service-sourced loop (`service_slice.run_service_loop`) into `make_data_modeller_body` / `model_data`. It is injected, so unit tests stay hermetic and a read blip degrades to the chunk-only index. (Option (b) of the finding: the `surface_survey` claims are prose, so option (a) could not be done cleanly.) REFINED by decision 23: the index as first written was PROJECT-WIDE and mis-anchored collisions; it is now unit-scoped and ambiguity-aware.
20. **A contracted Service with no pre-aggregated assets is dispatched (C-M2, MAJOR).** `run_service_loop` hard-skipped every empty unit as `no_surface`, so a Service with a `service_contract` but no aggregated surface could never discover its own. Under the batched variant (default), a unit whose `source_job` is `service:<slug>` and whose slug has a NON-EMPTY `service_contract` is dispatched even with no assets; discovery is the point. The bodies do not early-return on an empty admitted set for such a unit (`type_mechanisms`, `model_data`), so the workflow runs and records a genuinely-empty outcome if discovery finds nothing. A unit with neither a contract nor assets stays an explicit `no_surface` (ADR D15). The `legacy` variant keeps the hard skip. Bounded: one dispatch per unit, no fan-out. The contract gate needs the inventory; it is inert without an `inventory_fn`, so a caller injecting its own reads owns the seam. REFINED by decision 24: the dispatch is additionally bounded to a unit with discoverable surface (a non-empty BaseURL set), so unconfinable empty units stay `no_surface`.
21. **The residual unit is framed neutrally (B-M8).** The residual (`__residual__`) carries the surface no Service aggregates, but `_unit_kind` returned `Service` and the unit block put the FORWARD Service question with an empty contract. It is now `UNIT KIND: Residual` with a residual central question: which cross-cutting Systems the unaggregated surface evidences, and which are already mapped. The alternative (skipping the typist for the residual) was rejected - the residual surface still evidences mechanisms.
22. **The canonical note name is `modelling-closure` (C-m6).** The canonical key in `analysis/CONTEXT.md` is `<unit>:modelling-closure`; the data-modeller used the underscore variant `modelling_closure`. Both its prompt files (the batched rewrite and the retained `data-plane.md`) and the in-code `closure_note` prompt now use `modelling-closure`, matching the assigner and the mechanism-typist. The v2 data-modeller design doc is corrected in the same change (the legacy file no longer reproduces the underscore name byte-for-byte; the correction is deliberate). The edge-label catalogue is also single-sourced: the batched mechanism-typist prompt states the FULL 10-value `SYSTEM_EDGE_RELS` set, the `link` turn injects the `vocabulary` artifact, and a test asserts no `rel` is missing from the prompt.

## The streamed-mode guard (T5)

T1-T4 are scoped to the `service_sourced` pipeline - the ADR's whole subject.
The code applied them UNCONDITIONALLY to the shared `assign` body, so the DEFAULT `streamed` mode broke: it feeds job-keyed chunks (`chunking.chunks_for_job`; `source_job = job.tool`, e.g. `katana`), and the L1-unit-first discipline resolved that job name to a phantom Service (`SERVICE UNIT: katana`, `contract: (none)`), derived no candidate strings from an absent contract, halted at `falsify_harvest`, and wrote ZERO `AGGREGATES` - no `L1Service -> L0` edges.
Observed live: six streamed assigner pods (`httpx_0`, `katana_0..4`), zero aggregates each.

27. **The rewrite is scoped to `service_sourced`; `streamed` keeps the legacy slice-based assigner.** `assign` gains `unit_first: bool = True`. `unit_first=True` (the `service_sourced` passes `assign_services` / `assign_global`) runs the L1-unit-first `WORKFLOW`, the batched prompt file, and the `_unit_context_block` feed. `unit_first=False` (the `streamed` `make_assigner_body`, the supervisor's chunk-fed `ProposerBody`) runs the restored `WORKFLOW_LEGACY` (`surface_scan -> prior_insights -> candidate_owners -> assign -> closure`), the legacy `assigner.md` prompt file, the pre-fed `surface` artifact (`_slice_repr(l0_slice)`), and the legacy `_service_block`. The prompt variant and the workflow move TOGETHER: an L1-unit-first HOW over a slice-based workflow (or the reverse) is the mismatch the guard prevents.
28. **The mode is selected at the call site, never sniffed from the chunk shape.** `make_assigner_body` passes `unit_first=False`; the `service_sourced` passes keep the default. A chunk's `source_job` is not a reliable mode signal (a job name and a Service slug are both bare strings, and the batch adapter's source job is empty), so the caller - which knows the mode - owns the choice.
29. **`WORKFLOW_LEGACY` and `_service_block` are restored verbatim from the pre-T1 assigner (`dd8d376^`), and the loader takes an explicit variant.** `_load_assigner_skill` / `_system_prompt` accept a `variant`, so the streamed flavour loads `assigner.md` regardless of `ANALYSIS_PROMPT_VARIANT` (which still defaults to `batched_l1unit_first` for the `service_sourced` flavour). The streamed behaviour is therefore byte-comparable to what ran before the rewrite.

## The re-review fixes (T4b)

A second review of the T4 fix pass found the C-M1 index itself unsafe; all findings are fixed in the same change.

The decision on the SAFE shape of C-M1 was taken by READING THE SLICE BUILDER FIRST.
`service_slice.build_service_slices` builds each Service unit's assets from the aggregation rows, and the Assigner admits `Endpoint` alone, so a unit's chunk carries ONLY its aggregated Endpoints - never the Parameters/Headers/Secrets that hang off them (they land in the residual unit or nowhere). The unit chunk therefore does NOT already carry the sites, so the revert branch does not apply; the unit-scoped branch was taken.

23. **The discovered index is UNIT-SCOPED and ambiguity-aware (N1, MAJOR).** Treating the finding's first branch as unavailable: a Service chunk never carries the Parameters/Headers that hang off its aggregated Endpoints, so `read_surface_sites` must stay. But the union is now bounded to the unit: `_discovered_sites` keeps a Parameter/Header only when its `baseurl` is in `unit_baseurls(chunk, aggregations)` - the BaseURLs the unit's chunk carries plus those its aggregated Endpoints expose - so one Service's `surfaces_at` can never resolve to another Service's surface. A Secret is kept unscoped (its identity is the exact `value_hash`, so it carries no baseurl and no collision risk). `site_index` is split into `SiteIndex.exact` (the full identity) and `SiteIndex.by_name` (the bare name, present only when unambiguous); `_resolve_ref` matches the model's FULL identity when supplied and a complete-identity miss is a HARD drop, never a bare-name fallback - so a name colliding across two Services is not silently re-anchored, and a name mapping to more than one distinct identity is dropped from `by_name`. A regression test locks the reproduced collision (`id` on `/serviceA/thing` vs `/serviceB/thing`).
24. **A contracted-but-asset-empty Service is dispatched only with discoverable surface (N2, MAJOR).** Decision 20's dispatch was unbounded in aggregate - every contracted-empty Service spent two whole chains. It is now bounded to a unit with a NON-EMPTY BaseURL set (`unit_baseurls` again, read from the live aggregation view); a unit with neither assets nor baseurls stays an explicit `no_surface` (ADR D15). The `legacy` variant keeps the hard skip unchanged.
25. **The whole-project site read happens at most once per run (N3, MAJOR).** `run_service_loop` wraps `read_sites_fn` in a run-scoped memo (`_memorised_read`), so the graph is read once and every unit filters the one list, instead of re-reading and re-projecting the whole project per unit. The memo carries the fail-open behaviour: a read blip is cached as no discovered sites, so the gates degrade to chunk-only without re-attempting the read per unit.
26. **The graph-discovered index and the typist backstop slug are variant/role-honest (N4, N7).** `read_sites_fn` is wired in the production path through `_default_read_sites_fn`, which returns None under `legacy` - so the rollback reproduces the pre-change chunk-only gates (this is live because the unit-scoped branch kept the index, not the revert branch). The mechanism-typist's `UNIT:` line and its backstop `unit_slug` now use `_service_slug(chunk)` (the real, unsanitised Service slug), matching the data-modeller and the live inventory the contract is looked up in, instead of the sanitised `chunk_id`.

## Consequences

- The three new files start as verbatim copies, so the seam is testable before T1-T3 rewrite the content.
  A copy is not a behaviour change; it is the seam's placeholder.
- The default flips behaviour without a settings change.
  The rollback is one env var, `ANALYSIS_PROMPT_VARIANT=legacy`.
- The per-variant memo means a single process can serve both variants in tests without cross-contamination.
- Deleting the `legacy` files would break the rollback; they are retained until a measured comparison retires them.
- The variant selector is separate from `ASSIGNER_PROMPT_CONFIG` and `DATA_MODELLER_PROMPT_CONFIG`, which select the HOW-arm within a file, not the file.
- T1 removes the measured keep-0 defect: a Service no longer drops every proposal whose owner is another Service, because the write filter is gone while the global validation gate stays.
