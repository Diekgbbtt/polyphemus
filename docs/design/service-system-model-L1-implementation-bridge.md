## 3. Ranked "decide-first" set — the ≤5 one-way doors that gate everything

1. **Q1 — the two-store topology (L1D-1/L1D-2).** *Decision:* L1 lives as a disjoint `:L1*` label namespace + a second sole-writer in the same physical `neo4j:5-community`, with cross-layer refs as L1-node properties (not native edges). *Why irreversible:* it fixes how every L1 node is keyed, how every cross-layer ref is encoded, and where the L1D-25 judgment envelope physically sits; moving stores later re-writes the curator, the constraints, and every traversal. *Cheapest probe:* `grep -n "database=" agent/app/clients/neo4j_client.py` (empty ⇒ single default DB, community edition confirmed) + confirm the `:Service` collision (`schema.py:12`) — 2 minutes, collapses (b)/(c) immediately since a 2nd container/store buys nothing "independently navigable" that a label prefix doesn't, at real ops cost.
2. **Q7 — System/Service identity keys + the `__singleton__` sentinel (L1D-9/L1D-12).** *Decision:* `(project_id, system_kind, discriminator)` with `discriminator` a non-null string defaulting to `"__singleton__"`; Service `(project_id, business_function_slug)`; both hardened with `IS UNIQUE` constraints mirroring `endpoint_unique`. *Why irreversible:* identity is the one thing MERGE-idempotency and phase-2 rooting can't tolerate churning; a nullable discriminator silently duplicates Systems (`L1R-2`). *Cheapest probe:* `grep -n "IS UNIQUE" db/neo4j/schema.py` — confirms every existing key is non-null composite, so the sentinel must be a literal string; write one throwaway MERGE with `discriminator=null` twice and observe two nodes created (the trap) vs `"__singleton__"` → one.
3. **Q3 — Interface-B ⇄ D2 unification + registry columns (L1D-26).** *Decision:* one contract (`AnalyserReconRequest`, superset of D2's `{component,tool,template_set}`) + one executor (`request_targeted_recon(...)->list[PodExport]`, reusing `run_job`); `recon_jobs` gains `correlation_id, requester_id, origin` via idempotent `ALTER`. *Why irreversible:* the contract shape and the registry columns are what phase-2's block-and-reuse (`NM-2`) recycles; forking interface-B from D2 into two seams duplicates the pod-dispatch path the whole system reuses. *Cheapest probe:* read `recon-pipeline-forward-decisions.md:44-55` (D2's fixed signature) beside `pipeline.py:349-354` (`run_job` call site) — confirms they're the same seam and that sequential execution already makes a single out-of-band job trivial.
4. **Q5/Q4 — the typed spine cut + the skill interface (L1D-17/L1D-31).** *Decision:* freeze the spine slots (`api_paradigm`, `navigation_model`, `rendering_model`, `auth_methods`) and the anatomy-skill triple (classification→slot, evidence→Observation, probe→interface-B), generalising `_load_triager_skill` into `skill_for`. *Why irreversible:* retyping a spine slot or re-shaping the triple re-anchors every facet reference and every downstream signature (`L1D-19`); the NL side stays liberal precisely because the spine doesn't. *Cheapest probe:* `sed -n '405,485p' agent/recon/pod.py` — the `default_triage_fn` structured-output block is the exact shape the analyser/skill node copies; if it generalises cleanly, the interface is right.
5. **Q6 — preserve the endpoint-template key now (L1D-32).** *Decision:* write a derived `endpoint_template` on assignment even though the full reducer is `NM-10`. *Why irreversible:* it's the one §9.6 handle that must exist *at write time* — you cannot reconstruct templates from concrete paths after the fact without re-crawling; the spec wrongly assumed katana already provides it. *Cheapest probe:* `sed -n '1,53p' agent/recon/parsers/katana_parser.py` — proves paths are concrete, so the key is net-new and must be added at the assignment write, not assumed.
