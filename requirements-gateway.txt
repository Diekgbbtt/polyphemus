# Gateway dependencies (#100 LLM API gateway - litellm + models.dev glue).
#
# Layered on top of the redamon-agent base image in the Dockerfile like
# requirements-observability.txt: a litellm version bump is a ONE-FILE review,
# never a base-image rebuild (ADR D10).
#
# - `litellm`: the proxy ASGI (`litellm.proxy.proxy_server:app`) co-located
#   inside the agent container as a second ASGI process on the internal port
#   4000 (ADR D1). Pinned to the latest stable at install time
#   (operator-ratified 1.96.0, ADR D10). Bumping is a one-file review here.
#   The `[proxy]` extra is REQUIRED, not optional: `litellm.proxy.proxy_server`
#   imports `websockets` at module level and the `litellm` CLI imports
#   `uvicorn`, and neither is a base (non-extra) dependency of 1.96.0 - a
#   plain `litellm==1.96.0` install boots the proxy to a
#   `ModuleNotFoundError` (verified 2026-08-11 against the 1.96.0 wheel
#   metadata + source, in the D11 item-5 unit verification).
# - `fastapi`: the proxy's own requirement is `fastapi>=0.136.3,<1.0`, but the
#   upper end of that range is BROKEN for 1.96.0: fastapi 0.140.7 removed
#   `get_flat_dependant` from `fastapi.dependencies.utils` (verified 2026-08-11
#   by wheel search across 0.140.2..0.141.1), which
#   `litellm.proxy.management_endpoints.management_v1` imports at module level
#   - a container resolving a newer fastapi would crash at gateway boot
#   (`ImportError: cannot import name 'get_flat_dependant'`). 0.140.6 is the
#   newest release that still carries it; pinned here (verified against the
#   installed 1.96.0 proxy in the D11 item-5 unit verification).
#   starlette is NOT pinned: a fresh resolution picks starlette 1.6.0, which
#   boots the 1.96.0 proxy and round-trips chat completions unchanged
#   (verified in-process 2026-08-11).
# - `httpx`: the sync CLI (T2, #105) fetches the models.dev registry directly
#   at `https://models.dev/catalog.json` - there is NO separate "models.dev
#   client" package (ADR D10, verbatim). The agent already depends on httpx
#   transitively (it is the langchain/openai SDK HTTP transport); pinning it
#   here keeps the gateway's own fetch surface auditable and decoupled from the
#   agent's SDK pin.
litellm[proxy]==1.96.0
fastapi==0.140.6
httpx==0.28.1
